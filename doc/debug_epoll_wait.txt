高并发矛盾：epoll out 与 webbench 不符

最终定位与修复
时间：最后提交（processWrite 代码）。
进展：你发现 processWrite 在错误分支和空文件情况下未设置 iov 和 bytes_to_send，导致 write() 未发送数据。
解决：
修改 processWrite，统一设置 iov 和 bytes_to_send，确保所有分支正确准备响应。
修正空文件逻辑，从 return false 改为 break，保证数据发送。
关键收获
系统化 Debug 方法：
分层定位：从整体性能（连接数低）到主线程（epoll_wait 阻塞），再到具体函数（processWrite），逐步缩小范围。
日志驱动：通过添加时间戳（任务、主循环）和事件日志（epoll in/out），精确定位问题。
高并发服务器的理解：
事件处理：epoll_wait 的超时设置和 listen backlog 对并发能力的影响。
连接管理：keep-alive 和非 keep-alive 场景下连接关闭的必要性。
数据发送：HTTP 响应的完整性（头+体+发送）对客户端识别的关键作用。
代码逻辑的严谨性：
分支一致性：所有 switch 分支需统一设置输出缓冲区（iov 和 bytes_to_send）。
返回值检查：函数返回值的正确处理（如 processWrite 的 false）。
工具与验证：
webbench：理解其成功请求的判定标准（连接建立+响应接收）。
curl 和 netstat：手动验证响应格式和连接状态。
日志分析：从事件频率和时间戳推导代码行为。
